# AirWindow Forecast Artifact Contract

**Version:** 1.0.0 (draft for owner approval)<br>
**Schema:** `apps/airwindow/contracts/forecast.schema.json`<br>
**Runtime validator:** `apps/airwindow/contract_validation.py`

## Purpose

The AirWindow client will read one static, versioned JSON artifact generated by a future ML export command. It will not train or adjust the PM2.5 model. The artifact contains one record for each of the four monitored CPCB stations, with hourly station forecasts and the information needed to judge freshness, provenance, validation, and missing data.

No `forecast.json` is checked in or served today. The repository has no production inference/export path. The schema's test fixture is synthetic and exists only in `tests/test_forecast_artifact.py`; it must never be copied into the public data directory.

## Fields and semantics

- **Artifact:** schema version, unique artifact ID, generation time in IST, model issue time, and PM-history cutoff. These are separate timestamps. The PM cutoff must be no later than the model issue time.
- **Model:** stable model ID, model version, optional Git commit, and SHA-256 of the actual training data snapshot. Unknown values remain `null`; a value must not be inferred from a filename.
- **Weather:** `used` is explicit. When true, provider, model/run, and issue time are required. When false, these fields must be null. Weather issue time must be no later than the model issue time.
- **Station:** numeric location ID stored as a string, display name, actual latitude/longitude, latest PM observation time, freshness status/age/threshold, data completeness, station-level full-target validation metrics, and forecast records.
- **Forecast record:** target interval start/end, point prediction (or null if unavailable), `µg/m³`, forecast horizon, status, and an optional interval. Every intended hour is represented; a missing forecast has a null prediction and is never zero-filled. Timestamps are explicit IST and intervals must be exactly one hour.
- **Validation:** metrics are station-level, keyed by horizon, and use full-target RMSE as primary. For unavailable metrics, numeric values remain null. `n_targets` and fold count describe the evidence used to compute a measured metric.
- **Uncertainty:** intervals are null unless calibration status is `calibrated`, with method, fold count, nominal coverage and measured empirical coverage. The validator checks that an interval contains its point prediction.

Freshness has no project-wide age threshold yet. Until one is chosen and recorded in the artifact, use status `unknown`, leave `stale_after_hours` null, and provide a note. This prevents the UI from labelling old data fresh based on an invented threshold.

## Validation

`validate_artifact()` validates JSON Schema Draft 2020-12 plus temporal invariants: PM cutoff before issue time, weather issue before model issue, each target interval exactly one hour, horizons equal the time from issue to target start, contiguous hourly records including explicit missing hours, completeness counts match the records, and freshness age/status matches its stated threshold.

Tests use only an in-memory synthetic fixture. There is no real forecast data file in this commit. An ML export command must generate a real artifact, run this validator, and produce a manifest/hash before the frontend may load it.

## Approval gate

This is the proposed contract. Do not create the React/Vite frontend or populate `apps/airwindow/public/data/` until the repository owner approves this version. After approval, freeze this schema version for the first MVP and evolve it only with an explicit version change.
