# EXP-014 leakage audit

1. **PM cutoff:** `origin_features` filters Train to `target_start + 1h <= pm_cutoff`, then calculates elapsed-hour statistics separately by station. A future label injected at or after the cutoff leaves features unchanged in the focused test. Duplicate station-hours are rejected. Missing hours reduce observed-window counts and are never treated as zero.
2. **Target join:** `build_examples` constructs features before merging raw labels and asserts `target_end > prediction_origin`. Feature columns exclude `y`, target PM, `mean`, `count`, `available_at`, `series_id`, high-value flags, `ID`, `scoring_block` and row order. Target calendars and station one-hot values are known before issue.
3. **Model fitting:** At each validation origin, training examples satisfy `training.target_end <= validation.pm_history_cutoff`. This deliberately conservative purge also handles overlap between public and private target windows. The code rejects any later training label. Model residuals are computed only on eligible training rows from their own cutoff-safe W50 feature.
4. **Seasonal archive:** `AdditionalHistory.zip`'s 2024 observations precede all 2025–26 simulated origins. The existing loader, substring mapping, `legacy_doy` alignment and shared W50 fallback are unchanged. EXP-008's physical station/series ambiguity and archive timestamp semantics remain limitations for both W50 and supervised seasonal inputs.
5. **Weather and auxiliary data:** No forecast vintages with verified publication times and terms are present locally; observed future weather and reanalysis are excluded. No additional future-station data are used.
6. **Validation reuse:** Nine fixed development target days plus two known extreme stress days are exploratory. Earlier experiments inspected overlapping periods and rows. The model search is bounded and the stress dates were known before EXP-014; no result is presented as independent confirmation or a guaranteed public/private leaderboard gain.
7. **Inference parity:** On the current snapshot, the EXP-014 W50 feature equals production W50 for all 384 public/private target rows (maximum absolute difference zero). The complete 2,592-row W50 CSV reproduces reference SHA-256 `55e2fc8c7cad94db22f1358a8715216b0c7fbbb7a50c728c4413890f6a8716bc` under both the existing Python 3.13 environment and isolated Python 3.11 environment.

`available_at` is not verified first-publication time. The historical PM release/cutoff simulation is a proxy, not proof of when each label first became available to participants. No hidden labels were accessed and no Zindi submission was made.
