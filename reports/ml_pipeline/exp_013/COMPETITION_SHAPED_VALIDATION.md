# EXP-013 competition-shaped validation

The current private window is November 11 00:00 through November 12 23:00 IST, 48 target hours for each of four stations. The current official Train ends at November 2 23:00 IST. Thus the actual private PM observation-to-target leads are 193–240 hours, with each lead represented four times. The scoring time is the **target interval start**; the available PM time is the latest station-specific **interval end**.

`scripts/validate_exp013_competition_shape.py` uses the existing chronological `rolling_oof_seasonal` fold constructor with a 193-hour nominal gap, 48-hour target window, 7-day fold step and cutoffs at 23:00 IST. This yields midnight-start 48-hour windows. Historical PM is restricted to interval starts strictly before the cutoff, so the final eligible observation ends no later than the cutoff. The seasonal archive is from 2024 and predates all selected 2025–26 folds. The script then retains only **actual** station-specific leads in 193–240 hours and scores exactly the same keyed `(fold, station, target_start)` rows and unmodified labels for all four locked models. Each fold's simulated run time is `PM cutoff + 109h`, which is 84 hours before the first target midnight on the current live snapshot. Both target days share that issue time. No later PM is used. Output postprocessing uses the existing nonnegative seasonal OOF predictions and EXP-012 median function. The older `rolling_oof_seasonal` helper internally records prediction origin at target start; it does not use that field to compute PM or seasonal features. EXP-013 explicitly records the corrected pseudo issue, PM cutoff, target start and target end in its row audit, without changing predictions.

This construction produced **85 folds and 13,244 matched station-hours per model**, compared with 16,320 possible rows if all four stations had complete labels and exact private-style leads in every fold (81.15% coverage). Only **one** fold has all 192 rows. Actual selected leads range 193–240h, median 218h. Gaps beyond 240h caused by earlier station outages and absent labels are excluded from the primary matched comparison; the selection is independent of model predictions and target magnitude. The CSV outputs give fold, station and target-hour diagnostics. Historical lead counts are uneven, unlike the live private window's uniform four rows per hour, so the match is approximate. The available historical fold set cannot provide complete four-station windows at scale.

The four locked models are original W50 (`legacy_w50`), EXP-012 `0.5 × W50 + 0.5 × median24` (`hybrid_w50_m24`), `median72`, and EXP-011 month-day calendar W50 (`calendar365_w50`) as a diagnostic comparator. No weights or parameters were searched. `MODEL_COMPARISON.csv` contains separate historical-development and previously-inspected late-2026 partitions; `FOLD_METRICS.csv`, `STATION_METRICS.csv`, `HORIZON_METRICS.csv`, `LEAD_METRICS.csv`, and `NOVEMBER_METRICS.csv` contain detailed diagnostics. `horizon_hours` indexes 1–48 within each simulated target window; `pm_gap_hours` is the actual station-specific PM-to-target lead. The row-level output is an ignored local cache at `data/processed/exp013_row_predictions.csv.gz`; regenerate it with the validation script after running EXP-012's row-audit script. The 2024 source mapping, timestamp alignment and legacy calendar policy are unchanged.

**No independent confirmation set exists in this snapshot.** A keyed comparison against EXP-012's row prediction cache finds 100% of EXP-013 matched station-target rows were scored before, across its inspected gaps. The late-2026 partition is also explicitly reused from EXP-010/011/012. All model-selection evidence here is exploratory, despite using a closer horizon template. A new official Train release may provide fresh labeled rows, but only newly available, chronologically eligible rows would qualify as confirmation.
